WPML está bien cuando los idiomas viven en el mismo WordPress. Aquí no. `perugrandtravel.com` y `viaggiomachupicchu.it` son dos instalaciones, dos MySQL, a veces otro child theme. Instalar WPML en el inglés no le dice nada al italiano: otro hosting, otro `wp_posts`.

Polylang, TranslatePress y Weglot caen en lo mismo. Weglot además mete otro vendor y traducción automática. Con cuatro sitios ya partidos, el mapa tiene que vivir fuera.

## El diseño que sí encaja

Necesitas tres piezas, y ninguna es “un plugin premium de SEO”:

1. **Un mapa de equivalencias** URL ↔ URL, versionado, el mismo archivo en las cuatro instalaciones (o servido desde un sitio interno). JSON o PHP. Una fila por producto. Guion si no hay hermana.
2. **Un emisor** que, dada la URL actual, imprime el bloque recíproco completo: todos los idiomas existentes + autorreferencia + `x-default`.
3. **Un gancho** `wp_head` con prioridad conocida, que no pelee con Yoast. Si Yoast también emite hreflang (suele, si le das idiomas que no tienes), **apaga el de Yoast**. Dos bloques distintos es peor que cero.

```php
add_action('wp_head', 'pgt_emit_hreflang', 1);

function pgt_emit_hreflang() {
    $current = home_url(add_query_arg([], $GLOBALS['wp']->request));
    $block = pgt_hreflang_block_for($current);
    if (!$block) {
        return;
    }
    echo $block;
}
```

El detalle de `home_url` y permalinks con o sin slash final importa: el mapa tiene que usar **exactamente** la URL canónica. Si el mapa dice `/tour/x/` y WordPress sirve `/tour/x`, Google ve dos mundos. Elige barra final, 301 la otra, y el mapa sigue esa ley.

Un campo ACF “hreflang IT” editado por marketing es cómo se rompe la reciprocidad el martes a las 18:00. El mapa es código. Marketing pide “publica esta ficha en italiano”; sistemas añade la fila; el emisor hace el resto.
</Callout>

## Por qué el mapa no puede vivir en la cabeza de nadie

En un catálogo de 70 tours, las equivalencias no son traducción literal del slug. *Machu Picchu Full Day* vs *Machu Picchu 1 día* vs *Machu Picchu 1 giorno* vs *pacote Machu Picchu full day*. Cruzar sitemaps, no títulos. Los títulos mienten; los slugs, menos.

Gaps: si el lujo solo existe en inglés, el emisor **no** inventa un `hreflang="pt-BR"` a la home brasileña. Eso le dice a Google que el Grand Deluxe *es* la portada en portugués. Es una mentira de producto. El brasileño que aterriza en la home no compra el Belmond.

El mapa es también el backlog de marketing: cada guion es una ficha que ops ya opera y el mercado no puede comprar.

## Dónde se rompe en Goodlayers / Tourmaster

Temas de constructor y plugins de tours generan URLs en un CPT (`tour`, `pacote`). El emisor tiene que reconocer el CPT y el slug, no solo páginas. Si filtrás `is_page()` y te olvidas de `is_singular('tour')`, el hreflang vive en el blog y muere en el dinero.

Yoast a veces emite `hreflang` de “idioma del sitio” apuntando a sí mismo. Eso no es una red. Un único `hreflang="en"` autorreferente no agrupa nada. Quítalo o el informe de GSC se vuelve ruido.

Sitemaps: puedes **además** emitir en XML. No es obligatorio si el HTML es completo. Si haces las dos, que el mapa sea la misma fuente. HTML dice A, sitemap dice B: otra señal pisada.

## Cómo lo pruebas sin Search Console el día 0

```bash
curl -s -A "Mozilla/5.0" "https://www.agencia.com/tour/machu-picchu-full-day/" \
  | grep -oE 'hreflang="[^"]+" href="[^"]+"'
```

Pega la URL italiana que salió. Abre esa URL. El bloque tiene que listar **las mismas** cuatro (o N) URLs, incluido el inglés. Si el italiano no lista al inglés, no hay reciprocidad. Un script de 40 líneas ahorra una tarde de clics. El auditor en Python existe precisamente para eso: no para un informe bonito, para no desplegar un mapa cojo.

## Qué le dices al equipo de sistemas

No: “instalen WPML”. Sí: “el child theme ya tiene un `functions.php`; esto es un include más, idéntico en las cuatro, y un array. No toca el constructor. No toca Tourmaster. Si el permalink cambia, se cambia la fila.”

Eso es implementable un martes. WPML en cuatro sitios es un proyecto de vendor, licencias, y un modelo de datos que no coincide con la realidad. El SEO técnico que también escribe PHP no discute plugins. Trae el snippet y el mapa. El resto es disciplina de deploy.
