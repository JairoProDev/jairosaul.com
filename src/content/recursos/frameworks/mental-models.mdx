# Frameworks Mentales para Fundadores

Los mejores founders no tienen más información. Tienen mejores frameworks para procesar información.

## 1. First Principles Thinking

### Qué es
Deconstruir problemas hasta sus verdades fundamentales y reconstruir desde ahí.

### Cómo usarlo
```
Problema: "Lanzar un cohete cuesta $65M"

Pregunta: ¿Por qué?
→ "Porque así cuesta en el mercado"

First Principles:
→ ¿Cuál es el costo de los materiales?
→ Aluminio, titanio, combustible = $200K
→ ¿Por qué no construirlo nosotros?

Resultado: SpaceX
```

### Mi aplicación
- No aceptar "así se hace siempre"
- Cuestionar cada supuesto
- Reconstruir desde axiomas

### Cuándo usarlo
- Industrias estancadas
- "Imposibles" convencionales
- Innovación real

---

## 2. Inversion (Charlie Munger)

### Qué es
En vez de preguntar "¿Cómo tener éxito?", pregunta "¿Cómo garantizar el fracaso?"

### Cómo usarlo
```
Problema: ¿Cómo construir una gran startup?

Inversion: ¿Cómo garantizar que fracase?
→ No hablar con usuarios
→ Gastar todo el dinero en ads
→ No medir nada
→ Contratar demasiado rápido
→ Solucionar un problema que no existe

Solución: Hacer lo contrario
```

### Mi aplicación
- Lista de "cómo fracasar"
- Evitar esos errores religiosamente
- Via negativa: quitar > agregar

### Cuándo usarlo
- Planning estratégico
- Post-mortems
- Risk assessment

---

## 3. Second-Order Thinking

### Qué es
No solo consecuencias inmediatas, sino consecuencias de consecuencias.

### Cómo usarlo
```
Decisión: "Bajamos precios 50% para ganar market share"

First-order: ✅ Más clientes
Second-order: ❌ Percepción de low quality
Third-order: ❌ Difícil subir precios después
Fourth-order: ❌ Race to bottom con competidores
```

### Mi aplicación
- Jugar 3 movidas adelante
- Pensar en incentivos creados
- Evitar trampas obvias

### Cuándo usarlo
- Decisiones de pricing
- Hiring
- Fundraising terms

---

## 4. 80/20 Principle (Pareto)

### Qué es
80% de resultados vienen del 20% de esfuerzos.

### Cómo usarlo
```
Análisis:
- 20% de features → 80% de valor
- 20% de usuarios → 80% de revenue
- 20% de tiempo → 80% de output

Acción:
- Doblar down en ese 20%
- Eliminar el 80% que no mueve la aguja
```

### Mi aplicación
- Cohort analysis mensual
- Feature audit trimestral
- Time tracking semanal

### Cuándo usarlo
- Priorización
- Resource allocation
- Focus

---

## 5. Regret Minimization Framework (Jeff Bezos)

### Qué es
Proyéctate a los 80 años. ¿De qué te arrepentirías?

### Cómo usarlo
```
Decisión: ¿Dejar trabajo seguro para startup?

A los 80 años:
- ¿Me arrepentiré de no haberlo intentado? → SÍ
- ¿Me arrepentiré de fallar? → NO

→ Intenta la startup
```

### Mi aplicación
- Decisiones de carrera
- Grandes riesgos
- Oportunidades únicas

### Cuándo usarlo
- Career changes
- Big bets
- Life choices

---

## 6. Eisenhower Matrix

### Qué es
Urgente ≠ Importante. Prioriza por ambos.

### Cómo usarlo
```
          Urgente    No urgente
Importante  Do First   Schedule
No Imp.     Delegate   Eliminate
```

### Mi aplicación
- Todas las tareas en la matriz
- Q1: Do immediately
- Q2: Block time (lo más importante)
- Q3: Delegate
- Q4: Delete

### Cuándo usarlo
- Task management diario
- Sprint planning
- Time audits

---

## 7. Jobs to be Done (Clayton Christensen)

### Qué es
La gente no compra productos. Contrata productos para hacer un "trabajo".

### Cómo usarlo
```
No: "Vendemos milkshakes"
Sí: "La gente contrata milkshakes para hacer su commute menos aburrido"

Insight: Competencia = café, podcasts, muffins
No: Otros milkshakes
```

### Mi aplicación
- Customer interviews: "¿Qué trabajo necesitas hacer?"
- Competitive analysis diferente
- Marketing enfocado en el job

### Cuándo usarlo
- Product positioning
- Customer research
- Go-to-market strategy

---

## 8. Opportunity Cost

### Qué es
El costo real de algo = lo que sacrificas por ello.

### Cómo usarlo
```
Decisión: "Construir feature X"

Costo monetario: $10K
Opportunity cost:
- No construir feature Y (más impacto)
- 2 semanas de tiempo
- Complejidad añadida
- Technical debt

Costo real >> $10K
```

### Mi aplicación
- Cada "sí" es 100 "no"s
- Roadmap: qué NO construir
- Focus brutal

### Cuándo usarlo
- Roadmap planning
- Resource allocation
- Saying no

---

## 9. Circle of Competence (Warren Buffett)

### Qué es
Conoce tus límites. Opera dentro de ellos o expándelos conscientemente.

### Cómo usarlo
```
Dentro del círculo:
- Tech, startups, software

Fuera del círculo:
- Hardware, biotech, fintech complejo

Decisión: Stay in circle o expándelo (pero lento)
```

### Mi aplicación
- No invertir fuera del círculo
- No pivotar fuera del círculo
- Expandir: 1 área a la vez

### Cuándo usarlo
- Investment decisions
- Pivots
- Partnerships

---

## 10. Via Negativa (Nassim Taleb)

### Qué es
Mejorar quitando, no agregando.

### Cómo usarlo
```
Problema: "El producto es complejo"

No: Agregar tutorial
Sí: Quitar features innecesarias

Problema: "No tengo tiempo"
No: Agregar productivity tools
Sí: Eliminar meetings, distracciones
```

### Mi aplicación
- Feature removals > additions
- Simplificar código
- Time blocking = eliminar

### Cuándo usarlo
- Product simplification
- Life optimization
- Focus

---

## 11. Skin in the Game (Nassim Taleb)

### Qué es
No confíes en quienes no tienen pérdidas si se equivocan.

### Cómo usarlo
```
Advice:
❌ Consultor que cobra por hora
✅ Advisor con equity

Decisions:
❌ CEO sin skin in the game
✅ Founder con todo su tiempo y capital
```

### Mi aplicación
- Advisors: equity o nada
- Listen to: quienes han vivido el problema
- Ignore: teoría sin práctica

### Cuándo usarlo
- Hiring advisors
- Taking advice
- Partnership decisions

---

## 12. Antifragility

### Qué es
No solo resistir el caos. Beneficiarte de él.

### Cómo usarlo
```
Frágil: Un error = muerte
Resiliente: Aguanta errores
Antifrágil: Errores = aprendizaje + mejora

Ejemplo:
- 1 cliente grande = frágil
- 1000 clientes pequeños = antifrágil
```

### Mi aplicación
- Optionalidad > Plan perfecto
- Diversificar revenue
- Experimentar mucho

### Cuándo usarlo
- Risk management
- Portfolio approach
- Building resilience

## Cómo Usar Estos Frameworks

### 1. No los memorices, usalos
- Aplica 1 framework por semana
- Documenta resultados
- Compara decisiones

### 2. Combínalos
- First Principles + Inversion
- 80/20 + Opportunity Cost
- Second-Order + Skin in the Game

### 3. Enseña para aprender
- Explica a tu equipo
- Escribe sobre ellos
- Discute aplicaciones

### 4. Audita tus decisiones
- ¿Qué framework usaste?
- ¿Funcionó?
- ¿Qué mejorar?

## Red Flags

❌ Usar frameworks para justificar decisiones ya tomadas
❌ Analysis paralysis (pensar sin actuar)
❌ Dogmatismo ("siempre usa X framework")
❌ No adaptar a tu contexto

✅ Frameworks como herramientas, no reglas
✅ Combinar con intuición y data
✅ Iterar y mejorar
✅ Simplicidad > Complejidad

## Mi Framework para Usar Frameworks

```
1. Entiende el problema
2. Selecciona 2-3 frameworks relevantes
3. Aplica cada uno
4. Compara insights
5. Decide + Actúa
6. Mide resultado
7. Ajusta framework
```

El mejor framework es el que usas, no el que sabes.
